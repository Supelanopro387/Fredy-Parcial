## Sección 1 — El ciclo de vida del software
Todo proyecto de software recorre las mismas fases: requisitos, diseño, construcción, pruebas, despliegue y soporte. Cada fase tiene entradas, salidas y criterios de calidad. De un requisito a la operación: el software no termina cuando se programa, termina cuando funciona confiablemente en producción.

## Sección 2 — Requisitos y análisis
Antes de escribir código hay que entender quién usa el sistema y qué necesita resolver. Un requerimiento mal entendido se multiplica en retrabajos y demoras. La fase de análisis es la más barata de corregir y la más cara de ignorar.

## Sección 3 — Metodologías ágiles
El trabajo se divide en sprints: periodos cortos con entregas visibles. Un tablero ágil con columnas como Planear, Sprint, Pruebas y Entrega muestra el avance real del equipo. Cada iteración se revisa con el equipo y se registra: gestionar software es coordinar personas, versiones y riesgos con evidencia, no con promesas.

## Sección 4 — Bases de datos y sistemas de información
Los sistemas de información organizan los datos en entidades con llaves y relaciones: usuarios, solicitudes, estados. Las aplicaciones consultan y actualizan esos datos de forma confiable, y un buen esquema evita información duplicada o perdida.

## Sección 5 — Ciberseguridad desde el diseño
La seguridad no es una revisión final: entra desde el diseño. Validar entradas, limitar permisos y proteger los datos personales son parte de la calidad del software. Cada riesgo revisado a tiempo cuesta menos que un incidente después; la normativa vigente de protección de datos es la referencia obligatoria.

## Sección 6 — Arquitectura y gestión de proyectos
La arquitectura define los componentes del sistema y sus relaciones. La gestión del proyecto controla alcance, tiempo y calidad con evidencia documentada: el plan cambia si la evidencia lo pide, no si la prisa lo pide.

## Sección 7 — Despliegue y soporte
El sistema llega a producción con operación monitoreada y soporte continuo. El ciclo vuelve a empezar con cada mejora: nuevas solicitudes, nuevos requisitos, nueva versión. Gestionar software es mantener viva esa rueda.
